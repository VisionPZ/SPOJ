# ARITH - Simple Arithmetics

## Problem

Read one arithmetic expression per case: a positive integer, one of `+ - *`, and another positive integer, all on one line with no spaces. Print the calculation the way it is done by hand: the two numbers stacked, a rule, then the result, and for multiplication the partial products with their sum. A blank line follows every case, the last one included.

| Item | Bound |
| --- | --- |
| Cases `t` | about 1000 |
| Digits per number | 500 |
| Subtraction | second number always smaller |
| Leading zeros | none |
| Judge limits | 5 s, 1536 MB |

## Idea

Keep each number as a list of digit values, least significant digit first, so a carry only ever walks forward through the list. Add, subtract and multiply those lists with the same column rules learned in school; no big integer library is needed.

The layout follows from one number: how far the widest line reaches to the left of the digit columns, called `leftMost`. Shift every line right by that amount, and the block width becomes `lineWidth + shift`. One multiplication touches each digit pair once, 500 x 500 = 250 000 digit steps, and the printed layout contains those same partial products, so the output costs about as much as the arithmetic.

## Why It Works

Every line of the answer is one of four kinds: a number, a number with an operator in front, a rule of dashes, or a partial product. Once the column of each digit is known, the line is spaces plus digits.

Digit columns, counted from the right edge of the block:

| Line | Column of its last digit |
| --- | --- |
| first number | `blockWidth - 1` |
| operator plus second number | `blockWidth - 1` |
| partial product of digit `row` of the second number | `lineWidth - 1 - row + shift` |
| product (sum of the partials) | `blockWidth - 1` |

`row` counts the digits of the second number from the right, and `lineWidth - 1 - row` is the column of that digit before any shift.

A partial product may stick out to the left of the digit columns, because `first * digit` has more digits than the gap below that digit. That is why `leftMost` takes the minimum over the partial starts as well.

Worked example, generated by `gen.py`:

```
    325
  *4405
  -----
   1625
     0
 1300
1300
-------
1431625
```

`lineWidth` is 5, the digit `4` of `4405` sits in column 1, and `325 * 4 = 1300` needs column -2, so `shift` is 2 and the block becomes 7 columns wide.

## Code

Digits run least significant first, so `carry` only moves forward.

```nim
proc addReversed(first, second: seq[int]): seq[int] =
  var resultDigits: seq[int]
  var carry = 0
  var position = 0
  while position < first.len or position < second.len:
    var total = carry
    if position < first.len: total = total + first[position]
    if position < second.len: total = total + second[position]
    resultDigits.add total mod 10
    carry = total div 10
    position = position + 1
  while carry > 0:
    resultDigits.add carry mod 10
    carry = carry div 10
  return resultDigits
```

The loop runs `max(first.len, second.len)` times. `total div 10` is at most 1, so the trailing loop adds at most one digit.

```nim
proc subtractReversed(first, second: seq[int]): seq[int] =
  var resultDigits: seq[int]
  var borrow = 0
  var position = 0
  while position < first.len:
    var total = first[position] - borrow
    if position < second.len: total = total - second[position]
    if total < 0:
      total = total + 10
      borrow = 1
    else:
      borrow = 0
    resultDigits.add total
    position = position + 1
  return dropLeadingZeros(resultDigits)
```

`borrow` is only ever 0 or 1, and adding 10 once is enough because a digit minus a digit minus 1 stays above -10. `dropLeadingZeros` keeps the value 0 as the single digit 0.

One partial product per digit of the second number, which is exactly what the layout prints.

```nim
proc multiplyByDigit(first: seq[int], singleDigit: int): seq[int] =
  if singleDigit == 0:
    return @[0]
  var resultDigits: seq[int]
  var carry = 0
  for position in 0 .. first.len - 1:
    var total = first[position] * singleDigit + carry
    resultDigits.add total mod 10
    carry = total div 10
  while carry > 0:
    resultDigits.add carry mod 10
    carry = carry div 10
  return resultDigits
```

A zero digit prints the single digit 0, as the statement demands. `carry` stays below 10, so the trailing loop adds at most one digit.

The final product is the same digit pairs again, accumulated in place over a preallocated table.

```nim
proc multiplyReversed(first, second: seq[int]): seq[int] =
  var resultDigits: seq[int]
  var slot = 0
  while slot < first.len + second.len:
    resultDigits.add 0
    slot = slot + 1
  var row = 0
  while row < second.len:
    var carry = 0
    var column = 0
    while column < first.len:
      var total = resultDigits[row + column] + second[row] * first[column] + carry
      resultDigits[row + column] = total mod 10
      carry = total div 10
      column = column + 1
    var writePos = row + first.len
    while carry > 0:
      var total = resultDigits[writePos] + carry
      resultDigits[writePos] = total mod 10
      carry = total div 10
      writePos = writePos + 1
    row = row + 1
  return dropLeadingZeros(resultDigits)
```

The table has `first.len + second.len` slots, the closed form for the longest product. `resultDigits[row + column]` is the column that digit pair falls in, which is why the layout needs no extra summing pass.

`row` walks the digits of the second number from the right, and `partialStarts` records where each printed partial begins.

```nim
    var partials: seq[seq[int]]
    var partialStarts: seq[int]
    var row = 0
    while row < secondCount:
      var partial = multiplyByDigit(firstDigits, secondDigits[row])
      partials.add partial
      partialStarts.add (lineWidth - 1 - row) - (partial.len - 1)
      row = row + 1
    var productDigits = multiplyReversed(firstDigits, secondDigits)
    var leftMost = min(lineWidth - firstCount, lineWidth - secondCount - 1)
    var scanRow = 0
    while scanRow < secondCount:
      leftMost = min(leftMost, partialStarts[scanRow])
      scanRow = scanRow + 1
    if secondCount > 1:
      leftMost = min(leftMost, (lineWidth - 1) - (productDigits.len - 1))
    var shift = -leftMost
    var blockWidth = lineWidth + shift
```

`(lineWidth - 1 - row) - (partial.len - 1)` is the column of the digit minus the number of digits that hang to the left. `min` over the operator line and the product line covers the two other lines that can hang left, and `shift` moves them all back on screen.


Both numbers end at column `blockWidth - 1`, so the padding is their width subtracted from that. The first rule of dashes runs from the leftmost of the two operand lines to the right edge of the block.

```nim
    if secondCount > 1:
      var dashTwoStart = partialStarts[0] + shift
      var scanSecond = 1
      while scanSecond < secondCount:
        dashTwoStart = min(dashTwoStart, partialStarts[scanSecond] + shift)
        scanSecond = scanSecond + 1
      appendSpaces(outputBuffer, dashTwoStart)
      appendRepeat(outputBuffer, "-", blockWidth - dashTwoStart)
      outputBuffer.add "\n"
      appendSpaces(outputBuffer, blockWidth - productDigits.len)
      appendReversedDigits(outputBuffer, productDigits)
      outputBuffer.add "\n"
```

The second rule of dashes is skipped when the second number has one digit, because the statement then prints no sum. `dashTwoStart` is the leftmost partial product, not the leftmost of every line.

Input is read once into one string, then scanned by index; no token list is built.

```nim
proc readWholeInput(): string =
  var inputData: string
  var line: string
  while readLine(stdin, line):
    inputData.add line
    inputData.add "\n"
  return inputData

proc nextToken(inputData: string, scanPos: var int): string =
  while scanPos < inputData.len and inputData[scanPos] <= ' ': scanPos = scanPos + 1
  var tokenStart = scanPos
  while scanPos < inputData.len and inputData[scanPos] > ' ': scanPos = scanPos + 1
  return inputData[tokenStart .. scanPos - 1]
```

The blank lines the statement inserts are skipped by the `<= ' '` test. `tokenStart .. scanPos - 1` is one slice per expression, not per number.

Spaces are the largest part of the output, so they are appended in 8 KiB chunks from a doubling cache instead of one character at a time.

```nim
var spacePadding = " "
while spacePadding.len < 4096:
  spacePadding.add spacePadding
```

```nim
proc appendSpaces(buffer: var string, count: int) =
  var remaining = count
  while remaining >= spacePadding.len:
    buffer.add spacePadding
    remaining = remaining - spacePadding.len
  if remaining > 0:
    buffer.add spacePadding[0 .. remaining - 1]
```

`spacePadding` reaches 8192 characters by doubling, so a 500 digit indent costs one append. Output leaves the program in 512 KiB blocks.

## Complexity

Per case with `d` digits: `O(d^2)` digit steps for one multiplication, and the same `O(d^2)` characters printed. Addition and subtraction are `O(d)`.

Total for 1000 cases at 500 digits: about `2.5 x 10^8` digit steps and about 290 MB of output. Space is `O(d)` digits plus one 512 KiB output block.

The naive alternative, strings and repeated re-parsing, costs the same characters but rebuilds every line many times and writes per line.
