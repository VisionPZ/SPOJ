# Dynamic programming (90)

Most tables are O(n²) or O(n·budget), filled once and reused. Knapsack, interval and digit DP trade memory for a single sweep. Meet-in-the-middle halves the exponent.

| Code | Idea | Cost |
|---|---|---|
| [ACMAKER](ACMAKER/README.md) | Give each word a small set of tickets, one ticket for each possible letter it can donate, like choosing seats in a row. Count the tickets locally, then multiply choices across words with a running total. | O(1) |
| [ALIBB](ALIBB/README.md) | Treat each sweep as choosing which end to visit next, extending a collected block one item at a time. | O(n) |
| [AUTOMATA](AUTOMATA/README.md) | Treat each star as a bookmark you can move forward when a later letter fails. This is the classic greedy wildcard scan: consume letters directly, remember the last star, and retry from it on mismatch. | O(length of pattern + length of subject) per ordinary case |

| [BAT2](BAT2/README.md) | Picture two shelves: books rise on the left shelf and fall on the right shelf, and each book goes to at most one shelf. The algorithm is a two-track subsequence DP. | O(1) |
| [BAT3](BAT3/README.md) | Think of a slide with one elevator: you descend freely, and the elevator lifts you once at a marked stop. The algorithm runs two longest decreasing subsequence passes. | O(1) |
| [BAT4](BAT4/README.md) | Picture a hiker choosing the gentlest steepest step, like picking the easiest rung on a ladder. A minimax DP finds the smallest possible worst climb to every cell. | O(1) |

| [BIPCSMR16](BIPCSMR16/README.md) | Like seating guests at tables of three, avoid placing three people from one year at the same table. Spend the most crowded year two at a time and use the other years to fill the seats. For `k` teams, a year with count `c` supplies at most `2k` students, and all three years together supply `3k`. | O(input bytes) |
| [BISHOPS](BISHOPS/README.md) | Give each sloping lane at most one bishop, like parking one car per marked lane. A bishop never leaves its diagonal, so one bishop per lane already fills the board's capacity. | O(total input digits) |

Three rounds of row, column, row always suffice, so the program only tests whether 0, 1, or 2 rounds work. | [BOOKS1](BOOKS1/README.md) | Binary search the largest block sum, called the load. For a trial load, pack books greedily from left to right and count the scribes used. | [BOXES](BOXES/README.md) | Open the circle at one edge and solve the straight row, like sliding spare balls along a shelf until each slot holds one. | O(n²) per case, O(t·n²) total |
| [BUNDLE](BUNDLE/README.md) | Run a dynamic program over instruction prefixes. With only three slots, a bundle offers at most four stop positions. Keep the best state for each group size, ranked by fewest bundles, then fewest stops, then latest last stop. Think of packing boxes on a shelf: for each shelf length, remember only the arrangement that leaves the most room for later boxes. | O(t + n + states) |
| [BUS](BUS/README.md) | Treat a meeting as a channel that passes news both ways. For each bus pair, list the meeting minutes inside one least common multiple of the route lengths. That period is the first time both buses return to their start stations. Then propagate the earliest news arrival across the pairs. Think of passing a rumor along a chain of friends: the first time each friend hears it is all that matters. | O(n squared) |
| [BYTESM2](BYTESM2/README.md) | Keep only the best total that can reach each tile, like marking the highest score on each step of a staircase. Each tile looks at the three tiles above it and adds its own stones. | O(T · h · w) |
| [CALLS](CALLS/README.md) | Keep only prices that no two cheaper prices rebuild, like crossing names off a list. Once a price can be made from smaller ones, cross it off. | O(N^3) per flyer, O(t N^3) total |
| [CODEM4](CODEM4/README.md) | Think of the remaining row as a corridor with one door at each end, and each turn closes one door. Use interval DP keyed by the left and right ends. | O(T times size squared) |
| [COUNT](COUNT/README.md) | Add one truck at a time, like stacking one more step onto a staircase, and reuse every smaller count. The algorithm is dynamic programming over computers and trucks. | O(NK + Q) |
| [CRSCNTRY](CRSCNTRY/README.md) | A meeting is a checkpoint both cards visit in order, so the score is the longest common subsequence (LCS) length of the two cards. One bit mask per value packs the matches, so each checkpoint costs `m / 64` word operations, not `m` cell updates. | O(`n * m`) |
| [CSUBSEQS](CSUBSEQS/README.md) | Count each distinct string at the earliest place it can finish, like filing a book under the first shelf where the whole title appears. For a chosen first letter, use its first occurrence in each string. | O(26 S), with S reachable states |

| [GNY07H](GNY07H/README.md) | Treat the right edge of the grid like a stack of four slots that a domino can fill, like packing a bookshelf one shelf at a time. Track three counts: full grids, grids with two corner cells missing, and grids with two cells missing on one side. | O(C + Wmax) |
| [HANGLET](HANGLET/README.md) | Represent every register by a formula over the unknown starting bits, like writing one algebraic expression instead of trying every input value. Breadth-first search explores symbolic states (a program counter plus formulas) by cycle count. The first STOP gives the shortest time, and an exhausted queue gives HANGS. Each state costs O(n) diagram operations, with n at most 16. A concrete search over 2^32 register settings cannot finish. Takeaway: explore formulas, not bit patterns. | O(32 S) |
| [HELPBOB](HELPBOB/README.md) | Think of coupons as stamps collected while walking through a set of pizzas; a later pizza gets every stamp gathered so far. | [IITWPC4J](IITWPC4J/README.md) | Think of seating fish one at a time, with a checklist marking every aquarium already taken. Use subset DP over occupied aquariums. A mask records the taken aquariums, and its set-bit count tells which fish moves next. | O(T times n times 2 to the n) |

| [JARJAR](JARJAR/README.md) | Treat each possible piece count as a row of checkboxes, one box per reachable weight, like a chart that lights up when a new part is tried.
