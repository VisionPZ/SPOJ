# DCEPCA04 — Short Select (SPOJ)
<https://www.spoj.com/problems/DCEPCA04/>

## Problem

Count ten of the forty-four problems so that their combined accepted solutions reach a target. Print how many such selections exist.

Input has one hundred binary rows with forty-four entries each, then the target on its own line. Output one integer: the number of valid selections.

| item | bound |
|---|---|
| teams | 100 |
| problems | 44 |
| problems chosen | 10 |
| target X | 0 to 1000000000 |
| judge limit | 1574 ms, 1536 MB |

Each problem's column sum is the number of teams that solve it.

## Idea

Add problems one at a time and remember how many ways reach each score, like tallying running totals at a checkpoint. The tally has two axes: problems chosen and accepted solutions. Each problem adds one to the first axis and its column sum to the second. Visiting problems in reverse choice order keeps each problem used once.

One update per problem, choice count, and score keeps the table small.

## Why It Works

1. A selection is decided by the ten chosen problem indexes alone.
2. Its score is the sum of the ten matching column sums.
3. The table entry `ways` at (chosen, score) stores the count of partial selections.
4. Adding a problem shifts an entry by one choice and by that problem's column sum.
5. Processing choices downward stops the same problem from being added twice.

| term | meaning |
|---|---|
| `problemCounts` | accepted solutions for each problem |
| `ways` | count indexed by chosen problems and score |
| `acceptedCount` | column sum of the current problem |
| `threshold` | minimum accepted solutions required |

The sample has eleven problems solved by one team and thirty-three solved by none.

| step | visible value |
|---|---|
| largest possible score | 10 |
| threshold | 11 |
| selections reaching threshold | 0 |

Scores above one thousand are unreachable, so the table stops there.

## Code

**Input and scanner.** The reader loads the matrix and then parses integers by hand.

```nim
const flushBlockBytes = 1 shl 17
const teamCount = 100
const problemCount = 44
const selectCount = 10
const maxAccepted = teamCount * selectCount

var inputData = ""
var inputLine = ""
while readLine(stdin, inputLine):
  inputData.add inputLine
  inputData.add '\n'

var scanPos = 0

proc nextInt(data: string, pos: var int): int =
  while pos < data.len and (data[pos] < '0' or data[pos] > '9'):
    pos += 1
  var value = 0
  while pos < data.len and data[pos] >= '0' and data[pos] <= '9':
```

**Output helper.** One string collects all output before a single write.

```nim
  return value

var outputBuffer = ""

proc appendOutput(text: string) =
  outputBuffer.add text
  if outputBuffer.len >= flushBlockBytes:
```

**Counting table.** Each problem updates the table once, with choices in reverse.

```nim
    outputBuffer.setLen 0

var problemCounts = newSeq[int](problemCount)
for teamIndex in 0 .. teamCount - 1:
  for problemIndex in 0 .. problemCount - 1:
    let solved = nextInt(inputData, scanPos)
    problemCounts[problemIndex] += solved
let threshold = nextInt(inputData, scanPos)

var ways = newSeq[seq[int64]](selectCount + 1)
for selected in 0 .. selectCount:
  ways[selected] = newSeq[int64](maxAccepted + 1)
ways[0][0] = 1
for problemIndex in 0 .. problemCount - 1:
  let acceptedCount = problemCounts[problemIndex]
  var selected = selectCount - 1
  while selected >= 0:
    for accepted in 0 .. maxAccepted - acceptedCount:
      ways[selected + 1][accepted + acceptedCount] += ways[selected][accepted]
    selected -= 1

var totalWays: int64 = 0
for accepted in 0 .. maxAccepted:
  if accepted >= threshold:
    totalWays += ways[selectCount][accepted]
appendOutput($totalWays)
outputBuffer.add '\n'
stdout.write outputBuffer
outputBuffer.setLen 0
```

The first entry seeds the empty selection with zero chosen and zero accepted.
The reverse loop protects earlier choice counts from reuse in the same step.
The final sum collects every ten-problem selection at or above the threshold.

## Complexity

The table has one hundred one scores for each of eleven choice counts.

| phase | time | space |
|---|---|---|
| input read | 4400 integers | one input string |
| table init | 11 rows of 1001 counters | 11011 counters |
| problem updates | 44 times 10 times 1001 | unchanged |
| output | one line | block buffer |

| measure | Big O |
|---|---|
| time | O(P K S) with P = 44, K = 10, S = 1000 |
| space | O(K S) |

Enumerating all selections would test nearly two and a half billion subsets.

The table replaces that search with under half a million counter updates.
