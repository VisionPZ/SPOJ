## Problem

Cities sit on a circle and the arcs between them are passable clockwise (`C`), anticlockwise (`A`), or both (`B`). Read each test case's arc string and print the fewest new circles that carry one channel for every reachable ordered city pair. Two channels never share an arc.

| Quantity | Bound |
| --- | --- |
| Test cases | 100 |
| Cities per case | 3 to 100000 |
| Time limit | 17000 ms |
| Memory limit | 1536 MB |

The city count drives the design, so the work per case must stay linear.

## Idea

Count the reachable pairs whose two paths are both available, then subtract them from the capacity of the two travel runs. A clockwise circle carries fragments inside one run of clockwise-passable arcs; an anticlockwise circle does the same for the other direction. Each two-way pair can use either circle, so it removes one required circle from the total.

Cost per arc: one pass over twice the string to find the two run lengths, one pass to count two-way pairs.

## Why It Works

Let `L` be a run of `k` usable arcs. Its `k + 1` cities generate `(k + 1)` squared over `4` channels through the busiest arc. The two run lengths give the clockwise and anticlockwise circle counts before sharing.

A pair has two paths when the forward path crosses no `A` arc and the backward path crosses no `C` arc. Let `F` be the first blocking `A` after a city and `B` the last blocking `C` before it. The pair count adds `F - max(start + 1, B) + 1`.

Worked example for `BACB`, generated by the oracle in `gen.py`:

```
n=4  A=1  C=1  B=2
longest B/C run = 3  ->  capacity 4
longest A/B run = 3  ->  capacity 4
two-way pairs = 3
answer = 4 + 4 - 3 = 5
```

When one arc type is absent, every pair reaches its destination in the full direction. The `B` arcs form runs of passable arcs. Pairs inside one run can use either direction; all other pairs stay in the full direction. The busiest arc then carries the full load minus the saved pairs plus the best balance inside a run. All-`B` strings use the balanced split `(n squared) div 4`.

## Code

The input is read once and parsed by a hand scanner; output is flushed in blocks.

```nim
const firstDigitValue = 48
const flushBlockBytes = 1 shl 18

var inputData = ""
var inputLine = ""
while readLine(stdin, inputLine):
  inputData.add inputLine
  inputData.add '\n'

var scanPos = 0

proc nextInt(data: string, pos: var int): int =
  while pos < data.len and (data[pos] < '0' or data[pos] > '9'):
    pos += 1
  var value = 0
  while pos < data.len and data[pos] >= '0' and data[pos] <= '9':
    value = value * 10 + int(data[pos]) - firstDigitValue
    pos += 1
  return value

var outputBuffer = ""

proc appendOutput(text: string) =
  outputBuffer.add text
  if outputBuffer.len >= flushBlockBytes:
    stdout.write outputBuffer
    outputBuffer.setLen 0
```

The loop walks `cityCount` characters and stops at the newline. The `mod` in the second input line keeps the index in range.

```nim
let caseCount = nextInt(inputData, scanPos)
for caseIndex in 0..<caseCount:
  let cityCount = nextInt(inputData, scanPos)
  while scanPos < inputData.len and inputData[scanPos] != 'A' and
        inputData[scanPos] != 'B' and inputData[scanPos] != 'C':
    scanPos += 1
  let textStart = scanPos
  scanPos += cityCount
```

The three counts pick the formula. One-sided strings scan the `B` runs and balance the saved pairs inside each run.

```nim
  var anticlockwiseCount = 0
  var clockwiseCount = 0
  var bothWayCount = 0
  for k in 0..<cityCount:
    let arcChar = inputData[textStart + k]
    if arcChar == 'A':
      anticlockwiseCount += 1
    elif arcChar == 'C':
      clockwiseCount += 1
    else:
      bothWayCount += 1

  let cityTotal = int64(cityCount)
  let fullLoad = cityTotal * (cityTotal - 1) div 2
  var answer: int64 = 0

  if anticlockwiseCount == 0 and clockwiseCount == 0:
    answer = (cityTotal * cityTotal) div 4
  elif anticlockwiseCount == 0 or clockwiseCount == 0:
    var runLengths = newSeq[int]()
    var currentRun = 0
    let firstArc = inputData[textStart]
    let lastArc = inputData[textStart + cityCount - 1]
    for k in 0..<cityCount:
      if inputData[textStart + k] == 'B':
        currentRun += 1
      elif currentRun > 0:
        runLengths.add currentRun
        currentRun = 0
    if currentRun > 0:
      if runLengths.len > 0 and firstArc == 'B' and lastArc == 'B':
        runLengths[0] += currentRun
      else:
        runLengths.add currentRun
    if runLengths.len == 0:
      answer = fullLoad
    else:
      var bothPairs: int64 = 0
      var runCapacity = newSeq[int64](runLengths.len)
      for k in 0..<runLengths.len:
        let runSize = int64(runLengths[k])
        bothPairs += runSize * (runSize + 1) div 2
        runCapacity[k] = (runSize + 1) * (runSize + 1) div 4
      var prefixMax = newSeq[int64](runLengths.len)
      var suffixMax = newSeq[int64](runLengths.len)
      for k in 0..<runLengths.len:
        prefixMax[k] = if k == 0: runCapacity[k] else:
                       if runCapacity[k] > prefixMax[k - 1]: runCapacity[k] else: prefixMax[k - 1]
      for k in countdown(runLengths.len - 1, 0):
        suffixMax[k] = if k == runLengths.len - 1: runCapacity[k] else:
                       if runCapacity[k] > suffixMax[k + 1]: runCapacity[k] else: suffixMax[k + 1]
      var bestBalance: int64 = 0
      for runIndex in 0..<runLengths.len:
        let runSize = runLengths[runIndex]
        var outsideMax: int64 = -1
        if runIndex > 0 and prefixMax[runIndex - 1] > outsideMax:
          outsideMax = prefixMax[runIndex - 1]
        if runIndex + 1 < runLengths.len and suffixMax[runIndex + 1] > outsideMax:
          outsideMax = suffixMax[runIndex + 1]
        for take in 1..runSize:
          let base = int64(take) * int64(runSize - take + 1)
          if outsideMax >= 0:
            let candidate = base + outsideMax
            if candidate > bestBalance: bestBalance = candidate
          let lower = int64(take) * int64(take) div 4 + base
          if lower > bestBalance: bestBalance = lower
          if take < runSize:
            let vertex = (runSize + 1 + take) div 2
            var firstTry = vertex
            if firstTry < take + 1: firstTry = take + 1
            if firstTry > runSize: firstTry = runSize
            var secondTry = vertex + 1
            if secondTry < take + 1: secondTry = take + 1
            if secondTry > runSize: secondTry = runSize
            let valueOne = int64(firstTry) * int64(runSize + 1 + take - firstTry) -
                           int64(take) * int64(take)
            if valueOne > bestBalance: bestBalance = valueOne
            if secondTry != firstTry:
              let valueTwo = int64(secondTry) * int64(runSize + 1 + take - secondTry) -
                             int64(take) * int64(take)
              if valueTwo > bestBalance: bestBalance = valueTwo
      answer = fullLoad - bothPairs + bestBalance
```

The doubled scan finds each cyclic run once. It runs over `2 * cityCount` positions and caps at `cityCount`.

```nim

    var longestClockwiseRun = 0
    var currentClockwiseRun = 0

      else:

      if arcChar == 'A' or arcChar == 'B':
        currentAnticlockwiseRun += 1

      else:

    if longestClockwiseRun > cityCount:

```

The two distance arrays cost one backward and one forward sweep. Adding `cityCount` before `mod` avoids a negative index.

```nim
    let unreachable = cityCount
    var stepsToA = newSeq[int](cityCount)
    var stepsToC = newSeq[int](cityCount)
    for k in 0..<cityCount:
      stepsToA[k] = unreachable
      stepsToC[k] = unreachable

    for k in countdown(2 * cityCount - 1, 0):
      let position = k mod cityCount
      if inputData[textStart + position] == 'A':
        stepsToA[position] = 0
      else:
        let nextSteps = stepsToA[(k + 1) mod cityCount] + 1
        stepsToA[position] = if nextSteps > unreachable: unreachable else: nextSteps

    for k in 0..<2 * cityCount:
      let position = k mod cityCount
      if inputData[textStart + ((k - 1 + cityCount) mod cityCount)] == 'C':
        stepsToC[position] = 1
      else:
        let nextSteps = stepsToC[(k - 1 + cityCount) mod cityCount] + 1
        stepsToC[position] = if nextSteps > unreachable: unreachable else: nextSteps
```

One pass over the cities sums the two-way pairs. Each city contributes a clamped interval length.

```nim
    var bothReachablePairs: int64 = 0
    for startCity in 0..<cityCount:
      var forwardEnd = startCity + stepsToA[startCity]
      if forwardEnd > startCity + cityCount - 1:
        forwardEnd = startCity + cityCount - 1
      let backwardStart = startCity - stepsToC[startCity] + 1 + cityCount
      var low = startCity + 1
      if backwardStart > low:
        low = backwardStart
      if forwardEnd >= low:
        bothReachablePairs += int64(forwardEnd - low + 1)
```

The final subtraction uses 64-bit arithmetic, since the answer can exceed 32 bits.

```nim
    let clockwiseCapacity = int64(longestClockwiseRun + 1) *
                            int64(longestClockwiseRun + 1) div 4
    let anticlockwiseCapacity = int64(longestAnticlockwiseRun + 1) *
                                int64(longestAnticlockwiseRun + 1) div 4
    answer = clockwiseCapacity + anticlockwiseCapacity - bothReachablePairs
```

## Complexity

Input and output use one buffer each; output stays under one line per case. Counting arc types takes `O(n)` time and no extra space. The doubled run scan takes `O(n)` time and constant space. The two distance arrays take `O(n)` time and `O(n)` space. The pair sum takes `O(n)` time. Total time is `O(n)` per case and total space is `O(n)`. A direct search over pair directions would take exponential time.
