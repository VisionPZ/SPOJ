# VAPI01 — Vitaliy and Pie (SPOJ)

<https://www.spoj.com/problems/VAPI01/>

## Problem

A walker crosses rooms in a line. Each room holds one key, and each door needs the matching key. Find how many keys he must buy before the walk so that he reaches the last room.

Input starts with a test count T. Each test has a room count n, then a string of length 2·n − 2. Odd 1-based positions hold lowercase keys for rooms 1..n − 1. Even positions hold uppercase doors leading to the next room. Print one integer per test: the fewest keys bought.

| item | bound |
|---|---|
| tests T | 1 to 100000 |
| rooms n | 2 to 100000 |
| string length | 2·n − 2 letters |
| judge limit | 100 ms, 1536 MB |

A key opens one door and is then gone. Keys bought before the walk can open any door of the same letter.

Sample input:

```
1
3
aAbB
```

Sample output:

```
0
```

## Idea

Spend a key when its door arrives, like using the next ticket in a wallet; if no ticket waits, buy one.

The algorithm is a single left-to-right scan with 26 counters, one per key letter. Each room adds one counter, and the following door either spends a counter or adds one purchase. Cost is O(n) per test and O(1) extra state. A search over buying choices would branch at every door and grow exponentially. A running count keeps the choice forced and cheap.

## Why It Works

1. Room i gives its key before the door out of room i appears in the string.
2. A held key of the door letter always works, since letters match by case alone.
3. Spending that key now cannot hurt later doors of the same letter.
4. If no key is held, buying one is the only way past the door.
5. Purchases for different letters never help each other, so the greedy count is optimal.

| term | meaning |
|---|---|
| `plan` | the alternating key and door string |
| `availableKeys` | held keys left for each letter |
| `neededKey` | letter index of the door being crossed |
| `boughtKeys` | running number of purchased keys |

The worked example uses the sample string generated by the cases below.

| step | letter | action | `availableKeys` for a and b | `boughtKeys` |
|---|---|---|---|---|
| room 1 | `a` | store key a | 1, 0 | 0 |
| door 1 | `A` | spend key a | 0, 0 | 0 |
| room 2 | `b` | store key b | 0, 1 | 0 |
| door 2 | `B` | spend key b | 0, 0 | 0 |

The walk finishes with zero purchases, matching the sample output.

Each counter resets per test, so no key leaks across cases. Letter indices are taken from the two ASCII bases, so no case conversion routine is needed.

## Code

**Input and helpers.** The reader loads stdin once, then supplies integer and letter-token scanners plus a block-buffered writer.

```nim
const flushBlockBytes = 1 shl 17
const alphabetSize = 26
const lowerBase = 97
const upperBase = 65

var inputData = ""
var inputLine = ""
while readLine(stdin, inputLine):
  inputData.add inputLine
  inputData.add '\n'

var scanPos = 0

proc nextInt(data: string, pos: var int): int =
  while pos < data.len and (data[pos] < '0' or data[pos] > '9'):
    pos += 1
  var value = 0
  while pos < data.len and data[pos] >= '0' and data[pos] <= '9':
    value = value * 10 + int(data[pos]) - 48
    pos += 1
  return value

proc nextToken(data: string, pos: var int): string =
  while pos < data.len and data[pos] <= ' ':
    pos += 1
  var token = ""
  while pos < data.len and data[pos] > ' ':
    token.add data[pos]
    pos += 1
  return token

var outputBuffer = ""

proc appendOutput(text: string) =
  outputBuffer.add text
  if outputBuffer.len >= flushBlockBytes:
    stdout.write outputBuffer
    outputBuffer.setLen 0
```

The token scanner skips whitespace and returns the next run of letters.
The output buffer flushes after 128 KiB and once more at the end.

**Greedy scan.** Each pair of letters is one room and one door, handled in place.

```nim
let caseCount = nextInt(inputData, scanPos)
var availableKeys = newSeq[int](alphabetSize)
for caseIndex in 0 .. caseCount - 1:
  let roomCount = nextInt(inputData, scanPos)
  let plan = nextToken(inputData, scanPos)
  for letterIndex in 0 .. alphabetSize - 1:
    availableKeys[letterIndex] = 0
  var boughtKeys = 0
  var doorIndex = 0
  while doorIndex < roomCount - 1:
    let keyLetter = plan[2 * doorIndex]
    availableKeys[int(keyLetter) - lowerBase] += 1
    let doorLetter = plan[2 * doorIndex + 1]
    let neededKey = int(doorLetter) - upperBase
    if availableKeys[neededKey] > 0:
      availableKeys[neededKey] -= 1
    else:
      boughtKeys += 1
    doorIndex += 1
  appendOutput($boughtKeys)
  outputBuffer.add '\n'
stdout.write outputBuffer
outputBuffer.setLen 0
```

The room key is added before its door is read.
A positive counter means the door is free, and zero means one purchase.
Counters are cleared at the start of every test.

## Complexity

The scanner reads one string per test and writes one line per test.

| phase | time | space |
|---|---|---|
| input read | one pass over the string | one input string |
| door scan | one step per door | 26 counters |
| output | one line per test | block buffer |

| measure | Big O |
|---|---|
| time per test | O(n) |
| space per test | O(1) beyond input |

Trying every buy-or-spend choice would explore an exponential set of walks.
The scan decides each door once and finishes in linear time.
